# 跟随官方 MinerU 升级的维护流程

## 原则

以官方新版本的架构为事实基础，再决定如何整合本 Fork 的必要功能。**不要机械地覆盖官方文件，也不要无条件保留每一行旧定制。**

Fork 曾以 `mineru-4.0.12-released` 作为起点；之后是否仍对应此版本，应在每次升级前依据提交历史、Tag、实际版本号重新确认，不能只相信本文件的历史记录。

## 升级前

1. 明确本次升级的官方目标 Release/Tag、当前 Fork HEAD 与最后一次合入的官方基线。
2. 备份可用版本或记录可回退的镜像版本；确认 Docker 模型缓存和运行数据位置。
3. 阅读官方变更记录与涉及文件的上游差异，特别是 Router、API、JobStore、VLM runtime、CLI、Dockerfile、WebUI。
4. 阅读 `CUSTOMIZATIONS.md`，列出每一项定制是“仍需保留”“官方已经覆盖”“需要适配”还是“可删除”。
5. 明确本次涉及的完整文件与 Git blob SHA，不依靠截取片段复原源码。

## 冲突处理优先级

1. 优先理解官方新实现和行为，不仅做文本层面的冲突合并。
2. 对空闲卸载，重点检查任务异步锁、取消/清理、生命周期、vLLM shutdown/reload 和新模型缓存实现。
3. 对 CLI，检查所有层级：Router → Worker → Typer 中转 → Click → create_app，避免遗漏参数。
4. 对 Docker，检查镜像依赖、模型下载选项、BuildKit 缓存挂载、容器网络、健康检查和显存约束。
5. 若上游已经提供等价可靠功能，优先删除冗余定制并更新文档；不要并行保留两个空闲回收机制。
6. 修改越界时明确说明；未经需求要求不重构无关模块。

## 分层验证

**静态与轻量**：Python 语法、CLI `--help`、参数验证、目标单元测试、Compose 配置检查。

**容器启动**：Router healthy、WebUI 启动、`/v1/health` 与 `/v1/tiers`。

**实机回归**：上传小 PDF 跑 Hybrid；确认 Markdown / JSON 下载；确认首次加载、空闲卸载、显存下降、自动重新加载并再次解析成功；遇失败记录日志和浏览器错误。

**缓存检查**：看构建日志是否重复下载；对首次采用新 BuildKit 缓存导致的重新下载作预期说明。

不能因为“能启动”就认为“空闲卸载和下载全功能”均已通过。

## 升级完成后的文档维护

- 更新本目录 README 中的版本基线表述（应有证据）、定制清单及受影响路径。
- 补充改动的目的、原因、已删除旧实现和新验证结果。
- 修订部署命令与配置参数；记录尚未解决的异常。
- 保留清晰的变更证据在 Git 历史中，本文只陈述当前有效状态。

## AI 协作交付

用户主要采用 AI 辅助维护，并通过 git-bridge 完成同步。需要交付文件时，使用包含完整改动文件的增量 ZIP，仓库相对路径放在 `payload/`；仅删除、改名、移动旧文件时使用 ZIP 根目录的 `__delete__.txt`。

## 单 Dockerfile 与默认 WebUI 源码挂载

- 仅使用 `Dockerfile` 构建 `mineru:local`，不使用额外模型基础镜像。
- 模型下载在 `COPY .` 之后，构建缓存仍可能因源码改变失效；BuildKit 文件缓存与 `reuse_ready=True` 可减少重复下载。
- `reuse_ready=True` 不自动检查远端权重是否更新；修改模型注册表、权重版本或下载策略时，要明确验证和刷新旧模型。
- WebUI 默认挂载 `./mineru` 并使用 `PYTHONPATH`；只修改 WebUI 源码可重启 WebUI。Router/Worker 源码仍位于镜像内。
- 依赖、Dockerfile、模型、资源安装方式改变时，重建镜像并重新创建受影响的容器；更新 `.env`、Compose 配置需 `up -d`，不是 `restart`。

## Gradio 批量与历史回归

上游升级 Gradio 或改变 `File(file_count="multiple")`、`gr.Request` 自动注入、`gr.File` 的 `FileData` 事件、`.success()`、`gr.on` / 清除按钮行为时，应重点重测多文件输入适配、批次锁、旧转换回执、隐藏文件下载及刷新后恢复。

不得仅因页面有完整结果就推断会话状态已恢复；必须检查服务端历史索引和当前批次身份是否一致。上游若改变解析返回结构或 `RunArtifacts` 路径，复审 ZIP 与图床处理。
